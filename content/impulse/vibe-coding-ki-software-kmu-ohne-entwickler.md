## Das Wichtigste in Kürze

- **Vibe Coding** wurde im Februar 2025 von [Andrej Karpathy](https://de.wikipedia.org/wiki/Vibe_Coding) (OpenAI-Mitgründer) geprägt: Software durch Beschreiben statt Programmieren
- Laut Y Combinator haben bereits **25% der aktuellen Startups** Codebases, die fast vollständig KI-generiert sind
- Google-CEO Sundar Pichai: **Über 30% des neuen Codes** bei Google wird bereits von KI generiert
- Collins Dictionary hat "Vibe Coding" zum **Wort des Jahres 2025** gewählt
- Das Risiko: KI-generierter Code kann Sicherheitslücken enthalten – menschliche Überprüfung bleibt essenziell

---

"Wir bräuchten eigentlich eine kleine App für..." Ein Satz, den viele KMU-Inhaber kennen. Gefolgt von: "Aber dafür einen Entwickler zu beauftragen, ist zu teuer."

2025 ist das keine Ausrede mehr. Die Werkzeuge existieren. Die Frage ist nur: Kennen Sie sie?

## Was ist Vibe Coding genau?

Der Begriff stammt von [Andrej Karpathy](https://www.ibm.com/think/topics/vibe-coding), einem der Mitgründer von OpenAI und ehemaligem KI-Leiter bei Tesla. Am 3. Februar 2025 beschrieb er in einem viralen Tweet:

*"There's a new kind of coding I call 'vibe coding', where you fully give in to the vibes, embrace exponentials, and forget that the code even exists."*

Übersetzt: Du beschreibst in normaler Sprache, was du willst. Die KI schreibt den Code. Du akzeptierst das Ergebnis, ohne jede Zeile zu prüfen.

Klingt nach Zukunftsmusik? Laut [IBM](https://www.ibm.com/think/topics/vibe-coding) ist Vibe Coding "eine frische Herangehensweise, bei der Nutzer ihre Absicht in einfacher Sprache ausdrücken und die KI diese in ausführbaren Code verwandelt."

Der Begriff wurde so einflussreich, dass [Collins Dictionary](https://aimagazine.com/news/vibe-coding-the-future-of-code-or-just-a-short-term-con) ihn zum **Wort des Jahres 2025** gewählt hat.

---

## Was die meisten übersehen: Der echte Paradigmenwechsel

Die übliche Darstellung: "KI hilft Programmierern, schneller zu arbeiten."

Die eigentliche Revolution: **KI macht Nicht-Programmierer zu Software-Erschaffern.**

Der Unterschied ist fundamental:

| Alte Welt | Neue Welt |
|-----------|-----------|
| Entwickler schreibt Code | Anwender beschreibt Problem |
| Technisches Wissen nötig | Präzise Kommunikation nötig |
| Wochen für Prototyp | Stunden für Prototyp |
| Abhängigkeit von Experten | Eigenständigkeit möglich |

Laut [Google Cloud](https://cloud.google.com/discover/what-is-vibe-coding): "Vibe Coding senkt die Eintrittsbarriere für neue Entwickler und wirkt als Kraftmultiplikator für erfahrene Programmierer."

Die Kernkompetenz verschiebt sich: Nicht mehr "Code schreiben können" ist entscheidend, sondern "präzise beschreiben können, was man will".

Und raten Sie mal, wer das am besten kann? Die Menschen, die das Problem täglich erleben. Ihre Mitarbeiter. Sie selbst.

## Wer nutzt Vibe Coding bereits?

Die Zahlen sind beeindruckend:

**Bei Startups:**
Laut [Y Combinator](https://de.wikipedia.org/wiki/Vibe_Coding) – dem wichtigsten Startup-Inkubator der Welt – haben bereits 25% der aktuellen Startups Codebases, die fast vollständig KI-generiert sind.

**Bei Tech-Giganten:**
[Google-CEO Sundar Pichai](https://aimagazine.com/news/vibe-coding-the-future-of-code-or-just-a-short-term-con) bestätigt: Über 30% des neuen Codes bei Google wird von KI generiert.

**Bei Entwicklern:**
Eine Studie von Fastly zeigt: Bei einem Drittel der Senior-Entwickler ist mehr als die Hälfte des veröffentlichten Codes KI-generiert.

**Bei Nicht-Programmierern:**
Replit-CEO Amjad Masad: "75% unserer Kunden schreiben keine einzige Zeile Code selbst."

Das ist keine Spielerei für Technologie-Enthusiasten. Das ist die neue Realität der Softwareentwicklung.

## Konkrete Anwendungen für KMUs

Wo kann Vibe Coding in einem österreichischen KMU helfen?

### 1. Interne Tools

**Das Problem:** Sie brauchen ein kleines Tool, das genau zu Ihrem Prozess passt. Fertige Software ist zu generisch, Individualprogrammierung zu teuer.

**Die Lösung:** Beschreiben Sie das Tool in natürlicher Sprache. Die KI generiert einen funktionierenden Prototyp in Stunden.

*Beispiel:* "Ich brauche eine Webseite, auf der Mitarbeiter ihre Arbeitszeiten eintragen können. Pro Tag: Projektname aus Dropdown, Start- und Endzeit. Am Monatsende eine Übersicht als PDF."

### 2. Automatisierungen

**Das Problem:** Repetitive Aufgaben fressen Zeit, aber für einen Entwickler lohnt es sich nicht.

**Die Lösung:** Vibe Coding für kleine Skripte, die genau Ihren Workflow automatisieren.

*Beispiel:* "Schreibe ein Skript, das jeden Morgen die neuen E-Mails im Postfach durchgeht und alle mit 'Rechnung' im Betreff in einen Ordner verschiebt."

### 3. Prototypen für Kundenprojekte

**Das Problem:** Sie wollen einem Kunden zeigen, wie eine Lösung aussehen könnte – aber ohne wochenlange Entwicklung.

**Die Lösung:** Ein funktionierender Prototyp in einem Tag statt in einem Monat.

### 4. Datenauswertungen

**Das Problem:** Sie haben Daten in Excel, brauchen aber spezifische Analysen.

**Die Lösung:** Beschreiben Sie die gewünschte Auswertung, lassen Sie die KI den Code generieren.

## Die ehrliche Einschätzung: Wo sind die Grenzen?

Vibe Coding ist mächtig – aber kein Allheilmittel. Hier die ehrliche Einordnung:

### Was funktioniert gut:

- ✅ Schnelle Prototypen und MVPs
- ✅ Interne Tools mit überschaubarer Komplexität
- ✅ Automatisierungen und Skripte
- ✅ Webseiten und einfache Web-Apps
- ✅ Datenanalysen und Visualisierungen

### Was problematisch ist:

- ⚠️ **Sicherheitskritische Anwendungen:** KI-generierter Code kann Sicherheitslücken enthalten
- ⚠️ **Komplexe Systeme:** Bei großen Projekten wächst der Code über das hinaus, was ein Nicht-Entwickler verstehen kann
- ⚠️ **Langfristige Wartung:** Wer wartet den Code, wenn die KI ihn nicht mehr versteht?
- ⚠️ **Regulierte Bereiche:** Medizin, Finanzen, kritische Infrastruktur brauchen geprüften Code

[Karpathy selbst](https://simonwillison.net/2025/Mar/19/vibe-coding/) räumt ein: "Manchmal kann die KI einen Bug nicht beheben, dann arbeite ich drum herum oder bitte um zufällige Änderungen, bis er verschwindet."

Das ist für ein Wochenendprojekt akzeptabel. Für geschäftskritische Software nicht.

### Die Empfehlung von Raymond Kok (Mendix-CEO):

Laut [AI Magazine](https://aimagazine.com/news/vibe-coding-the-future-of-code-or-just-a-short-term-con): "Unternehmen dürfen dem Vibe-Coding-Trend nicht blind folgen, ohne die Auswirkungen auf die IT-Strategie zu berücksichtigen."

Meine Perspektive: Vibe Coding ist **perfekt für den Anfang** – Prototypen, Tests, interne Tools. Für produktionskritische Systeme braucht es immer noch professionelle Überprüfung.

## Was das für die Souveränität bedeutet

Hier kommt der Aspekt, den die meisten Vibe-Coding-Artikel übersehen:

**Wo läuft der Code?**

Wenn Sie mit Cloud-basierten Tools wie Replit oder Lovable arbeiten, liegt Ihr Code auf deren Servern. Das kann für interne Tools problematisch sein – besonders wenn sensible Geschäftsdaten verarbeitet werden.

Die Alternative: Lokale Tools wie Cursor arbeiten auf Ihrem Rechner. Der generierte Code bleibt bei Ihnen.

## Wie starten Sie mit Vibe Coding?

### Schritt 1: Klein anfangen

Wählen Sie ein Problem, das:
- Überschaubar ist (nicht geschäftskritisch)
- Klar definierbar ist
- Schnell testbar ist

*Beispiel:* Ein einfaches Formular für interne Zwecke.

### Schritt 2: Das richtige Tool wählen

Für Einsteiger empfehle ich:
- **Replit** (kostenlos starten, komplett im Browser)
- **Lovable** (für Web-Apps ohne Code-Kenntnisse)
- **Claude** (für Skripte und Automatisierungen)

### Schritt 3: Präzise beschreiben

Je genauer Sie beschreiben, was Sie wollen, desto besser das Ergebnis. Statt "Ich brauche eine App" besser: "Ich brauche eine Webseite mit einem Formular, das Name, E-Mail und Nachricht erfasst und mir per E-Mail schickt."

### Schritt 4: Iterieren

Das erste Ergebnis ist selten perfekt. Beschreiben Sie, was nicht passt. Die KI verbessert.

### Schritt 5: Testen, testen, testen

Bevor Sie etwas produktiv nutzen: Testen Sie es gründlich. KI-Code kann subtile Fehler enthalten.
